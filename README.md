# Novagait Physical Therapy: Accessible Website Demo

[![CI](https://github.com/lotus-innovations/novagait-web/actions/workflows/ci.yml/badge.svg)](https://github.com/lotus-innovations/novagait-web/actions/workflows/ci.yml)

> Demonstration project by Lotus Innovations. "Novagait" is a fictional brand;
> all data is synthetic. Not affiliated with any real clinic or entity.

A before/after accessibility remediation showcase, modeled on the W3C WAI
["Before and After Demonstration"](https://www.w3.org/WAI/demos/bad/) pattern.
One fictional outpatient physical-therapy clinic site, shipped four ways:

| Surface        | Path                                                    | What it shows                                                                                                                          |
| -------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| After-site     | `/`                                                     | The remediated clinic site: 0 WCAG 2.2 A/AA axe violations, keyboard-clean, light + dark themes, reduced-motion aware, 400% zoom clean |
| Before-variant | `/before/*`                                             | The same pages with 12 realistic, documented accessibility violations (intentionally broken; noindex, banner)                          |
| Exhibit        | `/accessibility-demo`                                   | Side-by-side walkthrough: every seeded barrier annotated with the affected users, the WCAG 2.2 criterion, and the fix                  |
| Audit + VPAT   | `/accessibility-demo/audit`, `/accessibility-demo/vpat` | Machine-readable audit ledgers (before/after/diff) rendered in-page, plus a draft ACR (VPAT-style) for WCAG 2.2 A/AA                   |

## Why this exists

Lotus Innovations builds and remediates accessible web, mobile, and AI
products (WCAG 2.2 AA / Section 508). This repository is portfolio evidence:
the accessibility gate in CI fails the build on any WCAG 2.2 A/AA violation
on the after-site. Axe-clean is enforced, not claimed.

## Stack

- TypeScript, Next.js (App Router), Tailwind CSS v4; static-first, no backend
- `design-tokens.json`: the design system source of truth (palette, type
  scale, touch targets, motion policy). Every text/background pair is
  AA-verified by a unit test (`tests/unit/tokens-contrast.test.ts`)
- Vitest (unit), Playwright (e2e), axe-core via `scripts/a11y-gate.mjs` (CI
  accessibility gate; `/before/*` excluded by design)
- Deployed on Vercel, production at https://demo.lotusinnovations.io

## Local development

```bash
nvm use          # Node 22 (.nvmrc)
npm ci
npm run dev      # http://localhost:3000
npm run lint     # eslint + prettier check
npm run typecheck
npm run test     # vitest unit suite
npm run e2e      # playwright suite
```

## Repository layout

- `app/`: App Router pages (after-site, `/before/*`, exhibit, audit/VPAT)
- `content/`: synthetic fixtures (services, providers, locations)
- `audit/`: committed audit ledgers (`before.json`, `after.json`,
  `diff.json`, `vpat-starter.json`); nothing here is worth backing up, it is
  regenerated by rescans
- `scripts/a11y-gate.mjs`: repo-vendored CI accessibility gate
- `docs/`: spec (`SPEC.md`), architecture (`architecture.md`)

## Operations

- CD: Vercel Git integration; PR preview deploys, production on merge to
  `main`. No secret env vars in this project.
- Errors/logs: Vercel runtime logs. Analytics: Vercel Web Analytics.
- Demo data: static and synthetic; there is nothing to reset or back up.
